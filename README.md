## Підхід

MountainCar-v0 має неперервний простір станів (позиція, швидкість), тоді як
Policy/Value Iteration потребують табличної MDP з повністю відомою моделлю
переходів `P(s'|s,a)`. Тому простір станів дискретизовано на регулярну сітку
`300 x 300` (позиція x швидкість), а модель переходів побудована аналітично
на основі точної (детермінованої) фізики середовища — тобто це не
model-free навчання, а класичне планування за відомою моделлю.

Важливий нюанс: сила поштовху в MountainCar дуже мала (`force = 0.001`)
відносно діапазону швидкості (`0.14`). При грубій сітці (напр. 60x60,
ширина комірки швидкості ≈ 0.0024) ефект однієї дії менший за похибку
округлення до найближчої комірки — модель вироджується в шум, і отримана
"оптимальна" політика на практиці не долає гірку (0% успіху в реальному
середовищі). При `200x200` (ширина комірки швидкості ≈ 0.0007 < force)
аліасинг зникає, але при чесній оцінці на стандартному 200-кроковому
ліміті епізоду середня винагорода все ще трохи гірша за класичний поріг
"розв'язано" (-110): ~-114. Сітка `300x300` (ширина комірки швидкості
≈ 0.00047) дає 100% успіху та середню винагороду ≈-109 — обчислення
все ще займає долі секунди, тож дешевше просто взяти сітку дрібнішою.

## Структура коду

- `mountain_car_dp.py` — дискретизація простору станів та побудова
  детермінованої табличної MDP-моделі (`DiscretizedMountainCar`).
- `dp_algorithms.py` — векторизовані реалізації `policy_iteration` та
  `value_iteration`.
- `run_experiment.py` — точка входу: будує модель, запускає обидва методи,
  оцінює отримані політики в справжньому (неперервному) середовищі
  Gymnasium, зберігає графіки в `results/`.
- `mountain_car_mc.py` — on-policy first-visit Monte Carlo control
  (model-free) з potential-based reward shaping (`MCDiscretizer`, `mc_control`).
- `run_mc_experiment.py` — точка входу Лаб. 2: запускає Monte Carlo, Value
  Iteration та Policy Iteration, порівнює всі три методи, зберігає графіки.

Запуск:
```bash
pip install -r requirements.txt
python run_experiment.py       # Лаб. 1: VI vs PI
python run_mc_experiment.py    # Лаб. 2: MC vs VI vs PI
```

## Результати (сітка 300x300, γ=0.99, θ=1e-6)

Оцінка політик проводиться на **стандартному** ліміті епізоду Gymnasium
(200 кроків), без штучного розширення — це та сама умова, за якою
класично визначається поріг "розв'язано" (середня винагорода за 100
епізодів ≥ -110).

| Метрика                             | Value Iteration | Policy Iteration |
|--------------------------------------|:---------------:|:-----------------:|
| Час обчислення, с                    | 0.215            | 1.192              |
| К-сть розгорток до збіжності          | 112              | 94 покращень / 4962 розгорток оцінки |
| Success rate (100 епізодів, ліміт 200) | 100%           | 100%               |
| Середня довжина епізоду               | 109.3            | 109.3              |
| Середня винагорода (поріг solved: ≥-110) | -109.29       | -109.29             |
| Максимальна різниця V*(s)             | 0 (політики та V* ідентичні) | — |

### Незалежна перевірка коректності

- **Bellman-оптимальність**: для V* з Value Iteration залишок
  `V*(s) - max_a[R(s,a)+γV*(s')]` дорівнює **точно 0** на всіх станах.
- **Точність Policy Evaluation**: ітеративна оцінка політики в Policy
  Iteration порівняна з точним аналітичним розв'язком лінійної системи
  `(I-γP_π)V=R_π` (розріджений солвер) — розбіжність ~5.7·10⁻¹⁴
  (машинна точність), тобто це не наближення, а справжній розв'язок.
- **Самоузгодженість**: жадібна політика відносно фінального V*
  точно збігається з виведеною політикою на всіх нетермінальних станах.
- **Базова лінія**: класична евристика "штовхати в напрямку поточної
  швидкості" (bang-bang за знаком velocity) дає середню винагороду
  ≈-119.8 — отримана DP-політика не гірша (і трохи краща) за цю сильну
  евристику, що підтверджує її якість.

## Висновок

Обидва методи збігаються до **однієї й тієї ж оптимальної політики** та
функції цінності (що й очікується — для скінченної MDP з γ<1 оптимум
єдиний; підтверджено як точним нульовим Bellman-залишком, так і
незалежним лінійним розв'язком). Отримана політика — класична стратегія
"розгойдування" (energy pumping): штовхати машинку в напрямку поточної
швидкості, щоб накопичити енергію, перш ніж штовхнути її на вершину
гірки. У симуляції в реальному (неперервному) середовищі Gymnasium, під
стандартним 200-кроковим лімітом, ця політика розв'язує задачу зі 100%
успішністю та середньою винагородою -109.3 — що формально перевищує
класичний поріг "розв'язано" (-110).

Відмінності між методами — лише в обчислювальних характеристиках:
- **Value Iteration** збігається за менше "прохідних" розгорток (112) і
  значно швидше за часом (0.215 с), оскільки кожна розгортка виконує лише
  одну (векторизовану) операцію max по діях.
- **Policy Iteration** робить менше кроків *покращення політики* (94), але
  кожен крок вимагає повної збіжної оцінки поточної політики (сумарно 4962
  розгортки), що на цій задачі виявляється дорожчим за часом, попри менший
  зовнішній цикл. Це типова картина: PI зазвичай збігається за менше
  ітерацій "верхнього рівня", але VI часто швидше за сумарним часом,
  оскільки не вимагає точної оцінки політики на кожному кроці.

## Лаб. 2: Monte Carlo control (model-free)

На відміну від VI/PI, Monte Carlo не отримує модель `P`/`R` — навчається
виключно з реальних епізодів взаємодії із середовищем. "Наївний" MC не
працює на MountainCar: розріджена винагорода (-1/крок, 0 лише в момент
успіху) означає, що випадкова політика практично ніколи не досягає цілі
(~1.5% навіть за горизонт 2000 кроків), тож MC не отримує диференційного
навчального сигналу. Ані exploring starts (Sutton & Barto §5.3), ані
epsilon-greedy самі по собі це не виправили (0% успіху при чесній оцінці
навіть після 300k епізодів на сітці, що усуває аліасинг). Розв'язано
**potential-based reward shaping** (Ng et al., 1999): `F(s,s')=γΦ(s')-Φ(s)`,
`Φ(position)=100·sin(3·position)` — теоретично не змінює оптимальну
політику, але дає щільний сигнал прогресу. Результат: сітка 50×50,
100 000 епізодів, 370.8 с навчання → **98.0% success rate**, середня
винагорода -149.6 (проти 100% / -109.3 у VI/PI). Детальний опис усього
процесу адаптації — в `mountain_car_mc.py` та
`results/Lab2_MountainCar_MonteCarlo_Report.docx`.

| Метрика | Monte Carlo | Value Iteration | Policy Iteration |
|---|:---:|:---:|:---:|
| Тип методу | model-free | model-based (DP) | model-based (DP) |
| Сітка станів | 50×50 | 300×300 | 300×300 |
| Час обчислення, с | 370.8 | 0.176 | 1.018 |
| К-сть епізодів/розгорток | 100 000 | 112 | 94 покращення |
| Success rate, % | 98.0 | 100.0 | 100.0 |
| Середня винагорода | -149.64 | -109.29 | -109.29 |

**Висновок**: коли модель середовища відома (тут — з фізики MountainCar),
DP-методи незрівнянно ефективніші за часом і якістю. Model-free Monte
Carlo виправдано лише тоді, коли модель недоступна — і навіть тоді
потребує суттєвої адаптації (reward shaping) та грубішої дискретизації
(вибіркова складність), щоб взагалі навчитись.
